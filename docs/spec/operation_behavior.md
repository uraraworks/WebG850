# 実機の操作感 — 第三者の使用記録からの確認

`docs/spec/basic_commands.yaml` 等の底本はドイツ語／英語マニュアルだが、
マニュアル本文には「画面がどう振る舞うか」という操作感の記述が薄い。
ここでは、実機を操作した第三者による**使い方の解説記事**3本から、
これまで未確定だった操作仕様を確認する。

## 根拠の強さについて

**この文書の情報はすべて `verified_by: manual_3rd_party` 相当として扱う。**
`SCHEMA.md` の定義上は「第三者編纂のマニュアル」だが、ここでの出典は
マニュアルではなく個人サイトの**使用記録（ブログ記事・紹介記事）**であり、
`hardware`（自分で実測）ではない。実機実測で確定した事項とは明確に区別すること。

`verifiable_by_measurement` の観点では、いずれも「入力すれば誰でも同じ結果に
到達できる」操作感の記述であり `true` に相当する。ROM の逆アセンブルや
内部処理の解説ではない。

### SCHEMA.md への追記の要否（所見）

`SCHEMA.md` の `verified_by` には第三者の**使用記録・紹介記事・動画**を指す値が無く、
現状もっとも近いのは `manual_3rd_party` である。ただし「編纂されたマニュアル」と
「個人が使ってみた記録」は性質が違う（後者は断片的・網羅性が無い・機種を跨いで
書かれがちで対象機種の切り分けが難しい）。今後この種の出典が増えるなら
`usage_report_3rd_party` のような区分を切ることを検討する価値はあるが、
今回は `SCHEMA.md` を書き換えず、この文書内での注記に留めた。

## 確定した事項

### 1. カーソルは黒い■（ブロック）で点滅する

出典1に「カーソルキーを押すと黒い■のカーソルが点滅し、移動させることができる」旨の記述がある。

`src/basic/uncertain.ts` の `CURSOR_SHAPE`（`'block'`、これまでは根拠なしの暫定値）に
根拠が得られた。点滅すること自体も確認できたが、**点滅の周期（`CURSOR_BLINK_PERIOD_MS`）は
この記事からは分からず、依然として未確定**である。

### 2. `LIST` は簡易スクリーンエディタである

PRO モードで `LIST` を実行するとリストが表示され、**カーソルキーで表示位置を動かして
その場で修正できる**（出典1、出典2の双方に「↑↓でリストを見られる」旨の記述あり）。

これまで `basic_commands.yaml` の `LIST` を巡って「1画面ずつ止まって次を待つか、
流れ去るだけか」という問いを立てていたが、その立て方自体が実機の挙動に合っていなかった。
実際は「表示された状態で留まり、カーソルキーで送りながらその場編集する」方式である。

`LIST <行番号>` で指定行から表示できるという既存の記述（`basic_commands.yaml` の
「存在しない行番号ならその次に大きい行番号から表示」）とも矛盾しない。

### 3. 行番号だけを入力するとその行が削除される

出典1に同様の記述があり、実装済みの挙動（該当行番号のみの入力で行削除）を裏付ける。

### 4. PRO モードと RUN モードが存在し、`BASIC` キーで切り替える

数字で始まる入力を「行番号」と「計算式」のどちらとして扱うかを区別するため、
2つの動作モードに分かれている。PRO モードでは行として格納され、RUN モードでは
即時に計算式として評価される。画面右上に `RUN` / `PRO` の表示が出る
（出典1・出典2）。

出典3では、実機に `BASIC(ASMBL)` `TEXT` `RUN MODE` `PROGRAM MODE` `SHIFT` `2ndF`
`CAPS` の各キーが実在することが確認できる。

**既知の未対応として記録する**: 現在の実装は常時 PRO モード相当の動作をしており、
RUN モード（数字始まりの入力を即時評価する動作）が存在しない。

### 5. キーの実在

出典3により、以下のキーの実在が確認できる。ユーザー提供の実機写真とも一致する。

`BASIC(ASMBL)` / `TEXT` / `RUN MODE` / `PROGRAM MODE` / `SHIFT` / `2ndF` / `CAPS` /
`CLS` / `MODE` / および各種関数の独立キー

## 未確定のまま残る事項

### 入力待ちのプロンプト表示

現在の実装は `OK` を表示しているが、**これは MS-BASIC 系の慣行からの推測であり、
根拠が無い**。

一方、出典2には「RUN MODE / PROGRAM MODE では `>` のみが表示される」旨の記述がある。
ただしこの記事はシャープのポケコン全般（PC-E200 等を含む）を横断的に扱っており、
**この記述が G850V/VS 固有かどうかは確定できない**。

`OK` 説・`>` 説の両方を記録するに留め、現在の実装の `OK` が推測であることを明記する。

### エラー表示の実際の文字列

出典2に「`ERROR ●●` を `CLS` キーで消せる」旨の記述がある。一方、現在の実装は
エラー表示の先頭に `?` を付けているが、**この `?` はいずれの資料にも現れない推測**である。

### その他、記事からは分からなかった事項

- カーソルの点滅周期
- `CAPS` キーによる大文字/小文字切替の操作詳細
- `TEXT` / `CASL` / `STAT` インジケータの点灯条件
- 電源投入直後の画面表示

## 資料間の食い違い

出典1・出典3は PC-G850(V/VS) 系に焦点を当てているのに対し、出典2はシャープの
ポケコン全般（PC-E200 等）を横断して書かれており、`>` プロンプトの記述など
一部が G850V/VS 固有と確定できない。今回確認できた範囲では、3本の間で
直接に矛盾する記述は見当たらなかった（出典2の対象機種の広さが、確度を
下げる要因として残るのみ）。
