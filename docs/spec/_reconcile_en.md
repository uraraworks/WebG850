# 英語版マニュアルによる再検証記録 (2026-08-14)

底本: ドイツ語版(Jörg Wrabetz 編, v1.3, 2017) + 英語版(Jack W. Hsu 編, v3.0, 2018、独語版の英訳・改訂版)。
対象: `ocr_suspect` / `partial` / `needs_measurement` のいずれかが立っていた26件。

## 両版で内容が食い違った命令(要実測、最優先)

### CIRCLE
開始角・終了角の範囲を独語版は「0-360」と明記するが、英語版は「-360〜360」と明記した上で
「負値は原点から円弧への半径線を描く(扇形になる)、正値は弧のみを描く」と符号の意味まで説明する。
両版共通の実行例 `CIRCLE(71,23),20,-45,-135` は独語版自身の「0-360」という記述と矛盾しており、
独語側の範囲記述が単純な誤記である可能性が高いが、どちらが実機の実際の受理範囲かは実測しないと
断定できない。status を partial に据え置き。

### REC
本文(独語・英語とも同内容)は「変換された値は"x軸からの距離"・"y軸からの距離"として予約変数Y・Zに
割り当てられる」と説明しており、字義通り読めば Y=x軸からの距離(=y座標)、Z=y軸からの距離(=x座標)と
なるはず。ところが英語版の実行例 `REC(12,30)→10.39230485` に編集者注記「(x ≈ 10.4)」、続く
`PRINT Z`の結果6に「(y = 6)」が付いており、これをそのまま受け取ると「関数値=x座標、Z=y座標」で
本文の文言と正反対になる。独語版には数値例の出力自体が無くこの矛盾を裏付ける材料が無い。POLとの
対称性(POLはY=r,Z=θで本文と実行例が一致)から見てもRECだけ食い違うのは不自然。status を partial
に据え置き、実測が必要。

### RANDOMIZE
英語版は「既定の種は電源投入のたびに同一(RND使用時もプログラムの挙動が再現可能でデバッグに便利)、
RANDOMIZEを実行すると種を新しいランダムな値にリセットする」と明快に説明する(独語版にはこの説明が
無い)。ところが独語版の実行例では、プログラム冒頭にRANDOMIZEを置いたうえで電源をOFF→ONしてRUNし
直しても、5個の乱数列(2,1,10,8,10)が寸分違わず再現されており、英語版の「新しいランダムな値になる」
という説明と食い違うように見える。英語版は数値例そのものを収録していないためこの矛盾を裏付ける
独自データが無い。種の決定要因(内部カウンタ・実時間・操作タイミング等)は両版から確定できず、
status を partial に据え置き。

## 26件の分類

### 解決(ocr_suspect解除 or status引き上げ)— 18件

| 命令 | 内容 |
|---|---|
| ACS | 独語のOCR崩れ「-1 s X s 1」、英語は明瞭に「-1 ≤ expression ≤ 1」。両版一致で確定。 |
| ASN | 同上。独語「-1 _ X _ 1」→英語で明瞭化。 |
| DELETE | 独語の「Zeilenummer/Zeilennummer」綴り揺れは英語で単一表記「line number」。独語側のみのOCR/組版起因。 |
| DIM | 独語書式の角括弧の対応崩れは英語では発生せず、独語側のみのOCR起因と確認。 |
| DMS | 括弧無し実行例は、英語版で数学関数全般が「関数名 expression」表記である電卓モード呼び出し規則と判明し、書式不一致ではないと解決。 |
| EXP | 独語のeの近似値「2.7181828」(桁入れ替わり)に対し英語は「2.718281828…」と正しい値。独語側のみのOCR誤認。 |
| HCS/HSN/HTN | 独語付録Cの範囲表は3関数の行がOCRで入り乱れていたが、英語Appendix Cで3関数共通の範囲 -227.9559242≤x≤230.2585092 と明瞭に確認、独語の値そのものとも整合。 |
| MDF | 独語の用例はscreenshot画像で数値例が読めなかったが、英語版は通常テキストで同じ節を収録しており、DIGIT桁への丸め込み動作を具体例(55.4/9→MDF→6.156→*9=55.404)付きで確認できた。 |
| MOD | 独語には計算例が無かったが、英語版に整数除算(¥)とMODの対比計算例が多数収録されており、「両オペランドを四捨五入で整数に丸めてから0方向切り捨ての整数除算・剰余を返す」という具体的な丸め規則を初めて確認できた。 |
| NOT | 英語版5.4.4節にAND/OR/XOR/NOTのビット単位真理値表が実際の0/1値付きで収録されており、単純な全ビット反転(NOT X=-(X+1))と確定(タスク指示の通り)。 |
| POL | 独語は計算例が無くX/Y引数の対応が曖昧だったが、英語の実行例 POL(8,6)→10(r),Z≈36.87°(θ) から第1引数=x、第2引数=y、戻り値=r、Z=θと確定。 |
| PRINT->LPRINT | 見出し"PRINT->LPRINT"と本文構文"PRINT=LPRINT"の不一致は独語・英語共通の意図的な表記(見出しは切替の向き、構文は=)と確認、OCR起因ではない。 |
| VDEG | 独語の実行例出力「1. 51」はOCR崩れを疑っていたが、英語版で「1.51」と明瞭に出力され、かつ1°30'36"=1.51度という換算とも一致し、正しい数値だったと確定。 |
