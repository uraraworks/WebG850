# Phase 1 文法仕様

パーサの実装仕様。`docs/spec/basic_commands.yaml` の `phase: 1` にある 102 命令
（statement 33 / command 14 / function 49 / operator 6）を対象とする。

書式の出典は各命令の `format` フィールド。ここでは**パーサから見た構造**に整理し直す。
個々の引数の意味・範囲は YAML 側が正典なので、こちらには写さない。

## 行

```
行        := [行番号] 文 { ':' 文 } [改行]
```

- 行番号は 1〜65279（`RENUM` の記載より）。省略時はダイレクト実行
- `*ラベル` は行頭に置ける。`GOTO`/`GOSUB`/`RESTORE` の飛び先になる
- `REM` と `'` は行末までコメント。**`:` でも終わらない**
- `DATA` の引数も行末（または `:`）まで特殊に読む。通常の式パーサへ渡さない

## 式

優先順位（高い順）。**上ほど強く結合する。**

| # | 演算子 | 結合 | 備考 |
|---|---|---|---|
| 1 | `(式)` / リテラル / 変数 / 関数 | — | 一次式 |
| 2 | `^` | 右 | べき乗 |
| 3 | 単項 `-` `+` | 右 | `-2^2` は `-(2^2)` = -4 |
| 4 | `*` `/` `MOD` | 左 | |
| 5 | `+` `-` | 左 | `+` は文字列連結を兼ねる |
| 6 | `=` `<>` `<` `>` `<=` `>=` | 左 | 結果は真 -1／偽 0 |
| 7 | `NOT` | 右 | 単項 |
| 8 | `AND` | 左 | |
| 9 | `OR` `XOR` | 左 | |

**比較演算の結果について（訂正）**: 上表は当初「結果は真 1／偽 0」としていたが誤りで、
正しくは**真 -1（全ビット1）／偽 0**である。根拠は2つ。第一に `docs/spec/basic_commands.yaml`
の `AND` の `notes` が「比較式(真=-1/偽=0)同士に使うとIF文の論理AND条件としても機能する」と
明記している（5章冒頭 p.42 直前の表現規約）。第二に同 `NOT` の `notes` にある
`NOT X = -(X+1)` というビット単位の全反転定義と整合しない：真が 1 だとすると
`NOT 1 = -(1+1) = -2` となり、`-2` はビットパターン上も偽（0）ではなく非0＝真のままなので、
論理否定が成立しない。真が -1 のときだけ `NOT (-1) = -((-1)+1) = 0` と正しく反転する。
この誤りは実装の早い段階で「比較結果は 1/0 の慣行だろう」という推測から書かれたもので、
`AND`/`NOT` の根拠を突き合わせて発覚した。同じ推測を繰り返さないよう経緯を残す。

**`^` について**: `basic_tokens.yaml` に無いが、これは `^` が ASCII 文字であって
中間コード化される予約語ではないため。シャープ系ポケコン BASIC の慣行に従い実装する。
実測で存在が確認できたら `verified_by` を上げる。仮に存在しなくても、
使っていない作品には影響しない（omit する方が壊れる側）。

### 一次式

- 数値リテラル: 10 進（`1.5`, `1E-3`）、16 進（`&H1F`、`&1F` も可）
- 文字列リテラル: `"..."`。行末で閉じ忘れは許容する（実機の慣行）
- 変数: `A`〜`Z` ＋英数字。`$` 付きは文字列変数。`(...)` が続けば配列参照
- 関数: `basic_commands.yaml` の `kind: function` の 49 個。
  `PI` `FRE` `MDF` `INKEY$` は**引数も括弧も取らない**

**括弧なしの関数呼び出し（不確定仕様）**: 実在作品31本を機械解析した結果、
関数呼び出しで括弧を省略する書き方（`CHR$ 135` / `RND 6` / `VAL A$` / `LEN A$` など）が
29作品で常用されていることが分かった。引数1個の関数について `FN <引数>` の形
（`FN(<引数>)` に加えて）を受理する。引数2個以上の関数（`MID$` 等）は括弧必須のまま。

束縛の強さは**単項/一次式レベル**（上表の #1〜#3）に限る。根拠は、実在作品では
引数が複合式のときに作者が例外なく括弧を付けている（`CHR$ (140-B)`、
`INT ( RND (0` 等）こと。つまり `CHR$ 140-B` は `CHR$(140)-B`
（`CHR$(140-B)` ではない）と解釈する。マニュアルには括弧なし書式の記載が無いため
不確定仕様として `src/basic/uncertain.ts`（`UNPARENTHESIZED_CALL_BINDING`）に集約する。

### 変数名

実機は先頭 2 文字のみ有効（`ABC` と `ABD` が同一変数）という制約がある可能性が高いが、
YAML に記載が無いため**確定していない**。`src/basic/uncertain.ts` に
`VARNAME_SIGNIFICANT_CHARS` として集約し、暫定で「全文字有効」を採用する。

- 根拠: 2 文字制限を入れて誤って別変数を潰す方が、入れずに動く方より被害が大きい
- 実測またはマニュアル記載が見つかった時点で定数を直せば切り替わる

## 文

### 制御構造（ブロック構造を持つもの）

G850 BASIC は行番号ジャンプ型と構造化構文が同居する。パーサは**ブロックを AST に畳まず、
実行時にマッチングする**方式を採る。`GOTO` でブロックの内外へ自由に飛べるため、
静的な入れ子として組むと実機挙動から外れる。

| 構文 | 構成 |
|---|---|
| `FOR <var>=<式> TO <式> [STEP <式>]` … `NEXT [<var>]` | ループスタック |
| `WHILE <条件>` … `WEND` | ループスタック |
| `REPEAT` … `UNTIL <条件>` | ループスタック |
| `GOSUB <飛び先>` … `RETURN` | 呼び出しスタック |
| `IF <条件> THEN …` | 下記 2 形態 |
| `SWITCH <式>` / `CASE <並び>` / `DEFAULT` / `ENDSWITCH` | 実行時に前方走査 |

`IF` は 2 形態ある。**同じ `IF` トークンから始まるので、パーサが区別する。**

- **1 行形式**: `IF <条件> [THEN] <行番号>|*ラベル|<文> [ELSE <行番号>|*ラベル|<文>]`
- **ブロック形式**: `THEN` の後が行末 → 次行以降 `ELSE` / `ENDIF` までがブロック

判定基準は「`THEN` の直後にトークンがあるか」。無ければブロック形式。

**THEN の省略（不確定仕様）**: マニュアルの書式は `THEN` 必須（`format` に
`IF <条件> THEN …` としか無い）だが、実在作品31本を機械解析した結果、
`IF` の出現1063箇所のうち `THEN` 付きはわずか33箇所（97%が省略、28作品が使用）
だったため、マニュアルの記載より実測された使用実態を優先し `THEN` 省略を受理する
（`src/basic/uncertain.ts` の `IMPLICIT_THEN` 節に根拠を集約）。
`THEN` を省略した場合はブロック形式にはならず、必ず節（1行形式）が続く必要がある
（条件式の直後が行末・`:` なら構文エラー）。

`THEN` を省略した `IF` は連鎖できる
（`IF <条件1> IF <条件2> <文>` のように `IF` が入れ子になる書き方が常用される）。

**既知の制約**: `THEN` を省略した場合、条件式の直後に `*ラベル` を続けることはできない。
`*` は乗算演算子と同じトークンのため、条件式パーサが `IF A=1 *LOOP` を
「`A=1*LOOP` という乗算を含む条件式」として食べてしまい曖昧性を切り分けられない
（`THEN` 付きなら `THEN` が明確な区切りになるため問題にならない）。
実在作品の計測でもこの組み合わせは確認されていないため対応対象外とする。

### 飛び先

`GOTO` / `GOSUB` / `RESTORE` / `RUN` / `LIST` / `ON..GOTO` / `ON..GOSUB` は
`<行番号>` / `"<ラベル>"` / `*ラベル` の 3 形態を取る。共通の
`parseTarget()` に切り出すこと。

### PRINT

```
PRINT [USING "<書式>"] [ <項> { (',' | ';') <項> } ] [';']
```

- `,` は 12 桁ゾーン送り、`;` は連結、末尾 `;` で改行抑制
- `USING` は `PRINT` の引数リストの途中にも現れうる（書式の切り替え）
- 引数なしの `PRINT` は空行

### そのまま読めばよい文

`CLS` `END` `STOP` `RANDOMIZE` `CLEAR` `CONT` `NEW` `TRON` `TROFF`
`DEGREE` `RADIAN` `GRAD` は引数なし。`LOCATE` `GCURSOR` `PSET` `PRESET`
`PAINT` `LINE` `CIRCLE` `BEEP` `WAIT` `GPRINT` `DIM` `ERASE` `READ`
`INPUT` `LET` `DATA` `RESTORE` は YAML の `format` に従って素直に読む。

### 未対応の扱い

知らないキーワードに出会ったら、**黙って読み飛ばさず** `UnsupportedError` を持つ
ノードを作る。パース自体は次の行へ進めてよいが、実行時にそのノードへ到達したら
`?UNSUPPORTED <名前> IN <行番号>` を表示して停止する
（`docs/design/phase1_architecture.md`「未実装を無言にしない」）。

## 除外するもの

`phase: 2`（`CALL` `PEEK` `POKE` `OUT` `INP` 等 9 個）と
`phase: 3`（ファイル・プリンタ・PIC 等 25 個）は今回のパーサでは
**キーワードとして認識だけして `UnsupportedError` にする**。
「知らない綴り」と「Phase 1 の範囲外」を区別してメッセージに出すこと。
