# Phase 1 実行時仕様

インタプリタが持つ状態と、その更新規則。文法は `phase1_grammar.md`、
全体方針は `phase1_architecture.md` を参照。

## 実行位置

```ts
type PC = { lineIndex: number; stmtIndex: number }
```

行は**行番号順にソートした配列**として保持し、`lineIndex` は配列添字。
行番号 → 添字の対応表を別に持つ（`GOTO` のたびに線形探索しない）。

`GOTO`/`GOSUB`/`NEXT` は「行番号」ではなく `PC` を積む。`:` 区切りの複文の
途中へ `RETURN` で戻れる必要があるため、文単位の粒度が要る。

## 変数

| 種類 | 例 | 既定値 |
|---|---|---|
| 数値変数 | `A`, `X1` | 0 |
| 文字列変数 | `A$` | `""` |
| 数値配列 | `A(10)` | 全要素 0 |
| 文字列配列 | `A$(10)` | 全要素 `""` |

- 数値変数と文字列変数は**別の名前空間**（`A` と `A$` は別物）
- 単純変数と配列も別（`A` と `A(0)` は別物）
- `DIM` していない配列を参照したときの既定サイズは**マニュアルに記載が無い**。
  多くの BASIC は 0〜10 の 11 要素を暗黙に確保する。
  `uncertain.ts` の `IMPLICIT_ARRAY_SIZE = 11` に集約して暫定採用する
- 添字は 0 始まり（`DIM A(10)` で 0〜10 の 11 要素）
- `DIM A$(n)*m` の `*m` は 1 要素あたりの最大文字長。**超過分は切り捨てる**
- `CLEAR` で全変数を破棄、`ERASE` で指定変数のみ破棄

## スタック

3 本を**別々に**持つ。実機の BASIC は 1 本のスタックに混在させるが、
そこを真似ると「`FOR` の中から `RETURN`」のような異常系の挙動が
ROM 実装依存になり、観測なしには決められない。別々に持ち、
異常系は素直にエラーにする。

| スタック | 積む要素 |
|---|---|
| ループ | `{ kind: 'FOR'\|'WHILE'\|'REPEAT', pc, ... }` |
| 呼び出し | `GOSUB` の戻り先 `PC` |
| — | `DATA` ポインタはスタックではなく単一の位置 |

### FOR の判定順序

`FOR I=1 TO 0` は**ループ本体を 1 回も実行しない**か、1 回実行してから抜けるか。
マニュアルに記載が無い。`uncertain.ts` の `FOR_CHECKS_BEFORE_BODY = true`
（＝ 1 回も実行しない）を暫定採用する。

- 根拠: 判定を後に置くと `FOR I=1 TO 0` で配列外アクセスを起こす作品が壊れる。
  前判定の方が「壊れない側」

### NEXT の変数省略

`NEXT` は変数を省略できる。省略時はループスタックの最上位を閉じる。
`NEXT I` で指定された変数が最上位でない場合は、**その変数が見つかるまで
スタックを巻き戻す**（内側のループを暗黙に閉じる）。これは BASIC 共通の慣行。

## DATA / READ / RESTORE

- `DATA` は**プログラム全体を走査して収集**しておく（実行前に 1 回）。
  実行されない行の `DATA` も読める
- 読み取り位置は「何番目の `DATA` 項目か」の単一カウンタ
- `RESTORE` 引数なしで先頭へ、行番号／ラベル指定でその行の最初の項目へ
- 項目を読み切ってから `READ` すると `ERROR`

## 角度モード

`DEGREE` / `RADIAN` / `GRAD` で切り替わり、三角関数（`SIN` `COS` `TAN`
`ASN` `ACS` `ATN` `DMS` `DEG` 等）の解釈が変わる。既定は **DEGREE**
（ポケコンの慣行。`RADIAN` を既定にする BASIC とは逆なので注意）。

モードは `RUN` でリセットされるか維持されるか記載が無い。**維持**を暫定採用
（`uncertain.ts` の `ANGLE_MODE_RESET_ON_RUN = false`）。根拠は、
リセットする実装だと直前に `RADIAN` を打った利用者の意図が消えるため。

## 乱数

`RND(n)` と `RANDOMIZE`。**系列は実機と一致させられない**（`docs/spec` の
`RANDOMIZE` は不確定 3 件のうちの 1 つ）。

- `uncertain.ts` に PRNG 実装を集約する。線形合同法で決め打ち、シードは
  `RANDOMIZE` で現在時刻から与える
- **ここが実機と違うことをデバッグパネルに出す。** 乱数がずれても
  ゲームは普通に動いてしまい、誰も報告しないまま改善の機会が失われるため
  （親 `CLAUDE.md`「間違いが見えないと改善のループが回らない」）

## 中断と再開

| 事象 | 挙動 |
|---|---|
| BREAK キー | 実行を止め `BREAK IN <行番号>` を表示。状態は保持 |
| `STOP` | 同上（`STOP` 由来の表示にする） |
| `CONT` | 保持した状態から再開。`NEW`/編集後は不可 |
| `END` | 実行終了。状態は破棄しない（変数は残る） |
| エラー | `ERROR <番号> IN <行番号>` を表示して停止 |

`CONT` のために、停止時の `PC`・スタック・変数を丸ごと保持する。

## TRON / TROFF

`TRON` 中は行を実行するたびに `[<行番号>]` を画面へ出す。
実装は行の実行ループの先頭に 1 箇所だけ挟む。

## デバッグパネル（実装者向け）

常時警告はしないが、以下を後から確認できる場所に出す
（親 `CLAUDE.md`「不確定な仕様は知りたい人が確認できる場所に出す」）：

- 実行中に踏んだ**不確定仕様**の一覧（乱数・`CIRCLE`・`REC` ほか）
- `reportUnimplemented()` で記録された**部分未対応**の一覧
- 現在の角度モード・変数の数・スタック深さ
